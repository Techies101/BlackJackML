# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**21 Vision: AI Card Counter**: a live Hi-Lo card counter for an online blackjack table, with a PySide6 desktop UI. It captures a fixed 640×640 screen region, detects and tracks cards with a YOLO model, cross-checks each card's rank with a template-matching verifier, keeps the running/true count, and gives basic-strategy / deviation advice and a recommended bet. Windows-only, NVIDIA GPU (GTX 1650 Ti on an Intel + NVIDIA laptop). Private GitHub repo `Techies101/BlackJackML` (the repo/folder keep their original name).

## Environment and commands

Always use the project venv (VS Code is configured against it; the global Python has different packages):

```
venv\Scripts\python -m pip install -r requirements.txt       # install
venv\Scripts\python main.py                                  # run the app (needs the game on screen)
venv\Scripts\python experimentations\test_rank_verifier.py   # offline accuracy test of the verifier
venv\Scripts\python utilities\export_tensorrt.py [fp32|fp16] # rebuild + validate a TensorRT engine
```

There is no test framework, linter or build step. `test_rank_verifier.py` is the main regression check for rank reading: it scores the verifier leave-one-card-out (honest) and cross-corner (optimistic) on `card_templates/`, and writes per-step debug images to `rank_verifier_results/`. `test_trocr*.py` are abandoned TrOCR experiments.

## Architecture

- **Hide feed** (tab bar) shrinks the Main tab to a compact 446 px window (controls move under the left panel) and sets `CaptureWorker.show_feed = False`, so frames are neither drawn nor sent to the UI; counting continues.
- `main.py` starts dxcam, then builds the Qt app: `ui/main_window.py` (always-on-top, frameless, 1120×796; tabs Main · Basic Strategy · Deviations · Bet Spread) and `ui/logs_window.py` (Program Logs). The UI follows the Claude Design mockups in `BlackJackML screen designs/` (dark + neon; tokens and fonts in `ui/theme.py`, fonts bundled in `ui/fonts/`). The app icon (King + Queen + "21", simplified "21" at ≤ 32 px) lives in `ui/icons/` (`theme.app_icon()`); `main.py` sets an AppUserModelID so the taskbar shows it instead of Python's.
- `core/pipeline.py` `CaptureWorker` (QThread) loads the model, then while capture is on: grab frame → black out everything except the counting zone plus a small margin (`zone_mask()`, identical to the old `utilities/mask1.png` for the default zone) → `model.track` (ByteTrack) → count cards whose box **centre** stays in the zone for `REQUIRED_STABLE_SECONDS` with at least `REQUIRED_STABLE_FRAMES` sightings. All counting rules are **time-based** (`TrackState.now` = frame time) because cards sit in the zone only ~1 s and live FPS drops to 6–12 (uneven frames) while the game video plays and the screen is recorded; frame-count rules missed ~35% of cards. Safeguards for uneven frames: a card missing ≤ `MISS_TOLERANCE_SECONDS` keeps its progress; a new tracker ID that appears right after another vanished inherits its settling (or its counted status, if the rank glyph matches) via `find_predecessor`; a clearly-seen card that leaves before qualifying is counted on exit (`forget_missing`). While settling, every frame gets a YOLO class vote and a verifier read (until one scores `VERIFIER_ENOUGH_SCORE`); the best verifier frame (also the saved capture) and the most-voted YOLO class are used. Frame gaps over `STALL_WARN_SECONDS` are reported as WARNING logs. Validate counting changes by replaying a screen recording through `CaptureWorker` (crop the capture region from each frame, drive `time.monotonic` with video time) at every frame, a fixed low rate and irregular gaps → verifier second opinion (`decide_rank`: the verifier wins when YOLO conf < `YOLO_TRUST_CONF`, when it is "strong", or — safety net — whenever it is confident and its Hi-Lo group differs from YOLO's) → `ShoeCounter.add_card`. It emits annotated frames (`frame_ready`) and logs through `core/logbus.py`. Crops come from `clean_frame`, copied before any drawing.
- **Reused tracker IDs:** a new card landing on the same spot often inherits an already-counted ID. The pipeline stores each counted card's rank-glyph signature and re-counts the ID when both the YOLO class and the glyph change for `NEW_CARD_FRAMES` frames and `NEW_CARD_SECONDS` (a finger sliding the card away looks different for ~0.07 s).
- `core/counter.py` `ShoeCounter`: running count, cards dealt, burned cards, history (undo, ±1 corrections, burns, new shoe); shared by the capture thread and the UI, so it is locked. True count = RC ÷ decks remaining; bets/deviations use `true_count_int()`: the displayed 0.1 value rounded to the nearest whole number, halves away from zero (user's choice; the calculator's TC rows use the same rule). Burns are entered manually via the Burn popup (`ui/burn_popup.py`) because the dealer shows burn cards outside the counting zone: face-down burns only reduce decks remaining / advance penetration; face-up burns are also counted in the RC.
- `core/strategy.py` reads `strategy/basic_strategy.json` (BJA chart, with the S17 base for A,8 vs 6 = S and 11 vs A = H) and `strategy/deviations.json` (every index in `BJA_S17.pdf`; `0+`/`0−` mean positive/negative **running** count). `advise()` checks surrender first (fallback = the deviation-adjusted hard play), then pairs (Y/N splits with DAS), soft and hard.
- `core/betting.py`: ramp presets, EV / SD / risk of ruin / N-0 **estimates** from simulated true-count frequencies for the chosen decks/penetration (edge ≈ rules base + 0.5% per TC, fixed variance per hand); not a full hand simulation.
- `core/config.py` holds paths and tuning constants (default capture region and zone, thresholds, `ENGINE_PRECISION`); `core/settings.py` persists user settings to `settings.json` (git-ignored), including the live `capture_region` (moved with the **Capture area** button / `ui/region_picker.py`; dxcam is restarted on the new region, which works after CUDA init) and `zone` (dragged/resized on the live feed in `ui/main_tab.py` `FeedView`; right-click resets it). The feed's yellow zone is drawn by the UI, not the pipeline.
- `utilities/rank_verifier.py` (classic CV, not a neural net): find card contour → perspective-warp to a 280×200 **landscape** card → crop the rank from both corners (bottom-right rotated upright, avoiding 6/9 confusion) → 40×48 glyph → normalised cross-correlation against templates. A corner below `MIN_SCORE` counts as unreadable (e.g. covered by the dealer's hand), so one clear corner is enough for a confident read; two readable corners must agree. Same-rank glyphs score ≥ 0.87, different ranks ≤ 0.63.

## Data conventions

- `card_templates/` = verified, labelled cards used as verifier templates. Name: `<RANK>_<suit>_id<N>_<timestamp>.png`; rank is parsed from the first `_` token (`2`–`10`, `J`, `Q`, `K`, `A`).
- `captured_cards/` = new captures, named `<RANK>_unverified[_yolo<RANK>]_id<N>_<timestamp>.png`. The rank is only the pipeline's guess (`_yolo<X>` marks a YOLO/verifier disagreement). Filenames containing `unverified` are never used as templates; a human renames and moves them to `card_templates/`. Templates load only at startup; `drop_bad_templates()` skips any template corner that matches no other card of its rank at `TEMPLATE_MIN_MATCH` (e.g. half covered by the dealer's hand) and logs it as a WARNING.
- Suits don't matter to the verifier (images are binarized, suit symbol is discarded); 3–5 examples per rank matter.

## Gotchas

- **dxcam must be created before `ultralytics`/`torch` are imported.** On this Intel+NVIDIA laptop, Desktop Duplication fails (`COMError ... feature level is not supported`) once the process has initialised CUDA. `main.py` starts it first; `core/pipeline.py` imports ultralytics lazily inside `load_model()`. Keep torch out of module-level imports anywhere `main.py` imports before the worker starts.
- **Qt stylesheets override `setFont`:** never put `font-size`/`font-family` in `ui/theme.STYLESHEET`; fonts are set in code via `theme.font()` (pixel sizes, letter spacing).
- **Do not use `quantize="fp16"` / half precision with the `.pt` model:** on the GTX 1650 Ti it is slower (≈63 ms vs 37 ms per frame).
- `ENGINE_PRECISION` in `core/config.py` (`"fp32"` or `"fp16"`) selects `current_models/<model>.<precision>.engine`. It is used only when it exists and is newer than the `.pt`; otherwise the app warns and uses the slower `.pt`. After changing the `.pt`, rerun `export_tensorrt.py <precision>`: it keeps a new engine only if detections match the `.pt` on every template card, and restores the previous engine otherwise. fp32 matches the `.pt` exactly; fp16 is faster with confidences up to ~0.04 off. Engine files are GPU/TensorRT-version specific; `.onnx` files are export by-products.
- PaddleOCR was removed on purpose (1–2.5 s per card on CPU froze the feed, and misread cards). `opencv-python` is the only OpenCV package; installing `opencv-contrib-python` alongside it breaks `cv2`.
- Model load + warm-up takes ~10 s in the background (the first run after a reboot can take much longer); Start capture is enabled once it is ready. Live loop runs at ~35–47 FPS when the PC is idle, but 6–23 FPS while the game video plays and the screen is recorded; the app raises its own process priority to above normal.
